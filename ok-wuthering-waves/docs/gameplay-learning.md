# 剧情与活动学习

在「剧情与活动学习」页面启用自动记录，然后正常游玩。程序独立捕获游戏窗口，记录任务目标、交互提示、关键画面及非战斗操作。录制不需要快捷键标记。战斗区间的操作信息不会保存。

一次启用到停止对应一条完整记录。内部按照关键画面数量、停留和采集中断划分材料，界面中的记录列表和内容列表均按整次录制显示。停止后将整次录制的截图、观察和操作信息统一交给 AGY，步骤可以跨越内部片段边界。AGY 根据实际识别的任务或活动名称生成记录名称；手动修改名称后，后续分析会保留该名称。材料窗口包含整次录制的全部内部片段及对应材料。

停止录制并完成分析后，选择记录，点击「执行选中的完整记录」，也可以在内容列表选择该条内容后执行。程序检查全部片段、生成步骤的起止状态和前后连接，按照记录顺序处理全部内容。任何片段中断、缺少步骤、包含尚未支持的操作或无法连接时，完整记录显示需要处理，并说明对应原因。当前账号执行和多账号执行均使用同一完整顺序，每个账号分别保存各项内容的进度。

默认使用全局快捷键 `Ctrl+Shift+F8` 切换自动记录，在游戏前台和切换到其他页面时均可使用。学习页面的「录制切换快捷键」输入框支持直接按下新的组合键，修改立即生效并保存。按下 Esc 取消修改；按下 Backspace、Delete 或点击清空按钮可以停用快捷键。设置按键期间保持录制状态，释放组合键后才接受下一次切换操作。长按组合键只切换一次。

快捷键触发后，在当前前台窗口所在的屏幕中央显示录制状态提示，两秒后自动消失。提示不获取键盘焦点，鼠标操作可以穿过窗口。录制服务仍在结束时显示「正在停止录制」，已有异常导致无法开启时显示错误提示。

键鼠记录使用独立录制进程中的 Windows Raw Input。按键按下和释放使用 Windows 消息时间，保留长按时长；鼠标持续保存相对移动量、窗口内光标位置、按钮和滚轮事件。游戏固定光标位置时，相对移动量仍然保留。支持的按键包括 W/A/S/D、Space、Shift、F/T/Q/E、Esc、Tab、Enter、B/J/M/R/V、F1/F2。

截图采集每秒最多 20 张。处理进程取出前一张截图后才继续采集，OCR 和视频编码繁忙时，截图采集随处理速度调整，队列只保留一张待处理截图。键鼠记录独立运行，继续保存实际输入时间。识别与保存连续 30 秒没有响应时报告异常并中断当前记录。

画面发生变化时保存关键截图；画面稳定时按最后一次保存关键截图的时间检查一秒间隔，实际频率受采集与识别耗时影响。窗口最小化产生的采集缺口保留为中断证据，窗口恢复后继续保存后续片段。主动停止会结束采集，不增加采集缺口。

按住 Tab 打开工具轮盘、保持 Tab 时移动鼠标选择工具、释放 Tab、短按 T 使用当前工具，会保留各自的实际输入时序。片段交接保留前一观察和持有按键状态。战斗、登录、未知场景以及游戏失去前台期间的操作不进入可用操作证据。停止记录时补充结束画面，以核查末尾操作的结果。

原始轨迹逐条保存在 SQLite。AGY 接收按键状态变化及每组最长约 0.25 秒的轨迹摘要，摘要包含原始事件编号、光标起止位置、相对移动量和滚轮信息。原始样本保持不变。工具选择、驾驶与飞行可以生成 `input_sequence` 步骤，使用原始事件恢复按下、释放、持续时间及鼠标轨迹。该步骤只接受 W/A/S/D、Shift、Space、Tab、T、视角右键及工具轮盘内的左键，其他文字交互使用独立步骤。

轨迹步骤要求全部按键在证据区间内按下并释放，区间内没有战斗和采集中断，图像检查点间隔不超过两秒。执行窗口尺寸必须与录制时相同，鼠标与游戏镜头设置也需一致，光标显示状态必须与对应输入样本相符。执行前和执行途中使用环境特征的几何关系核查位置与视角；处理延迟超过 0.2 秒、图像不匹配或场景变化时释放按键并停止。独立输入监护线程检查窗口、暂停和停止状态，主执行线程超过 0.2 秒未响应时释放已经持有的输入。轨迹结束后，实际任务状态必须满足完成条件，才能继续后续内容。

完整结束的记录自动交给本机安装的 AGY 分析。AGY 返回带条件的流程数据；程序核对原始截图、观察记录、操作证据、步骤顺序和游戏版本。缺少证据的内容显示原因，不能进入执行队列。

在记录列表选择一条记录，点击「查看选中记录的材料」。材料窗口列出整次录像、关键截图、画面与任务识别、键鼠事件，以及已经生成的 AGY 分析请求、说明和结果。双击文件可以使用系统应用打开，也可以打开文件所在目录或记录材料目录。打开窗口时，将整次的记录信息、观察数据和操作事件分别导出为 `recording-details.json`、`observations.json`、`events.json`，并导出内部片段顺序和完整执行顺序；每段的原始文件也可以单独查看。正在录制时会显示提示，录像结束后才能完整播放。

录制诊断同时写入程序日志和 `diagnostics/<session_id>/` 下的 `capture.jsonl`、`worker.jsonl`，两份文件分别记录采集线程和处理进程。日志包含窗口存在、可见、最小化及前台状态，采集尺寸、截图等待时间、最后一帧的时间、画面中断及恢复、WGC 回调异常、识别耗时、场景变化和异常信息。每段的 `diagnostics.json` 保存结束原因、关键截图和视频帧数量、观察间隔，以及输入保存数量和按原因分类的排除数量。材料窗口可以直接打开这些文件；同次录制产生的多个片段共用会话日志。

## 正常使用

1. 在学习页面启用自动记录。记录目录、容量和 AGY 路径可以在任务设置中调整。
2. 正常完成剧情或活动。任务推进、场景变化和关键画面由程序识别。
3. 在学习页面查看已生成内容及验证状态，选择需要执行的内容。
4. 使用「从多账号日常导入账号配置」导入已配置的账号身份；没有账号配置时执行当前账号。
5. 点击「执行选中的内容」。每个账号分别保存进度，战斗调用现有 ok-ww 角色实现。

账号配置必须包含登录列表名称、区服标识和完整游戏内账号标识。导入时读取多账号日常已有配置，完整身份不符合要求时立即报告。登录后再次核查身份，核查完成前不执行剧情或活动。

程序使用游戏窗口的正常图像捕获及 Windows 输入，不读取或修改游戏内存，不修改游戏文件，不操作游戏网络数据。自动操作具有账号处罚风险。

## 中途停留

没有输入时继续观察。只有世界画面、任务和交互文字保持稳定，且没有战斗、加载或计时信息，才能确认停留。连续确认 30 秒后结束当前内部片段，整次录制保持开启并继续检测变化；重新出现操作或任务变化时开始后续内部片段。

对白、演出、加载和多波战斗保留对应状态。其他账号根据实际完成条件继续，不重复录制中的停留时长。切换到其他窗口后停止采集键鼠状态。

## AGY

使用已安装的 `agy-staff` companion，以受限权限和 `gemini-3.8-flash-low` 模型启动独立分析任务，通过 `wait` 收集最终结果。请求包含已遮蔽账号标识的截图、任务文字、必要操作证据和 JSON Schema。AGY 没有游戏输入权限。

默认自动寻找插件目录及 Node.js 18 或更新版本。可以在任务设置中指定 `agy-companion.mjs` 和 Node.js 路径。AGY 异常、权限不足或超时会停止分析并保留诊断；录制继续运行。失败的分析任务保留原始材料，不会自动重新启动。

「自动分析」独立于录制开关。停止录制后，分析线程处理已保存的完整记录，包括刚刚停止的本次录制；关闭「自动分析」后暂停领取待分析记录。程序退出时结束分析线程。

## 执行能力

| 动作 | 执行依据 |
|---|---|
| 导航 | 当前任务信标、距离变化、道路图像几何关系及攀爬体力；信标离开画面时原地转动视角搜索，无法确认方向或连续前进未取得移动结果时停止 |
| 交互 | 当前 F 提示对应的目标文字及操作后的任务、对白或机关状态 |
| 选项与领奖 | 当前画面中唯一且具有足够识别置信度的目标文字 |
| 对白 | 可见的对白推进提示；跨过整段对白时必须具有对应完成条件 |
| 等待 | 演出、加载或计时状态的实际结束条件 |
| 战斗 | 现有角色战斗实现；对白和演出中断战斗输入，分支选择需要原始截图文字范围与点击位置共同证明，后续波次继续根据场景判断 |
| 工具与移动轨迹 | 步行、跳跃、驾驶及飞行的完整非战斗键鼠时序，相同窗口尺寸、连续图像检查点及真实完成条件 |
| 简单机关 | 已观察到的 F 交互及明确的机关动作文字 |

需要尚未实现的随机机关求解、复杂三维定位或精确时机控制时，停止该内容并说明原因。仅有两张独立截图无法证明完整操作流程。

输入由同一执行线程管理，切换控制者时释放持有的按键。游戏失去前台、场景未知或程序异常时停止输入。Windows 拒绝激活窗口时会停止执行。

## 数据与恢复

默认目录为 `working_images/gameplay`。SQLite 保存记录环境、观察、流程版本、登录核查、账号进度和步骤尝试；录像使用分段 MKV，关键画面附带 SHA-256。

每次动作前保存尝试状态，完成条件连续确认后保存进度。恢复时核查保存的流程版本、步骤编号和游戏实际状态；步骤完成条件成立时进入下一步骤，执行前条件成立时继续该步骤。条件重叠或画面无法确认进度时停止；已确认完成的账号内容保持完成状态。

新分析使用基于任务名称、周期、期次、步骤动作与前后条件生成的稳定 `learned_v2_*` 编号。相同含义的完整内容重新录制后可以复用完成记录；同次录制中的重复内容分别保存进度。已有内容编号与进度保持原有，不自动合并。语言使用 `zh_CN`、`en_US` 等稳定编号保存。

删除材料时先保存待清理清单并提交数据库，再删除对应文件。Windows 文件占用等异常会直接报告，待清理项目保存在数据库中，程序再次启动时继续处理。未完成材料清理的流程不能执行。

流程分别显示「已生成」「已通过录像检查」「已通过游戏验证」。录像检查验证证据与定义；实际执行成功后保存账号、分辨率、语言、版本和结束画面，随后增加游戏验证记录。

一次性剧情、每日内容、每周内容和活动期次分别记录。每日按北京时间 04:00 更新，每周按周一北京时间 04:00 更新；执行开始时确定本次周期，中途跨过更新时间仍保留该次周期。

记录容量达到上限、磁盘空间不足、处理进程长时间没有响应或编码失败时停止记录并报告。采集异常时当前记录标记为中断。存在证据缺口的步骤无法通过检查。

## 验证命令

在项目目录使用仓库的 Python 环境：

```powershell
..\.venv\Scripts\python.exe -m pytest tests\TestGameplayLearning.py tests\TestGameplayLearningUi.py -q --basetemp=working_images\workflow-tests
$env:PYTHONPATH = '.'
..\.venv\Scripts\python.exe tools\verify_workflow_agy.py
..\.venv\Scripts\python.exe tools\verify_gameplay_runtime.py --seconds 15
..\.venv\Scripts\python.exe tools\verify_gameplay_input.py
..\.venv\Scripts\python.exe tools\verify_workflow_playback.py
..\.venv\Scripts\python.exe tools\verify_workflow_execution.py
```

AGY 验证使用真实截图检查结构化返回及证据不足时的处理。窗口录制验证不发送游戏输入。轨迹输入验证在独立 Windows 窗口中核查实际按键、鼠标轨迹、时序与停止释放。执行验证进入当前账号并核查资料页面，不执行剧情、活动或资源消耗。验证结果与画面保存在 `working_images` 中。完整游戏任务及车辆、飞行全过程需要分别具备实际执行证据，独立窗口验证仅证明输入传递能力。
