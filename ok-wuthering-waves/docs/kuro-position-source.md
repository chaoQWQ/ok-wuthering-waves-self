# 库街区位置同步

地图高价值物品显示提供“自动选择”“仅截图 OCR”“仅库街区同步”三个坐标来源选项。库街区直接连接目前仅供账号 3 使用；本地收集档案为 `13452871892`，游戏角色 UID 为 `112136276`。

## 设置与使用

1. 在“实时触发 → 地图高价值物品显示”中启用任务，选择账号 3 的收集档案 `13452871892`，坐标来源选择“自动选择”或“仅库街区同步”。
2. 打开“库街区位置同步设置”，确认账号 3 的 token 已保存。更换 token 时，在窗口中输入新 token，核对游戏角色 UID `112136276`，勾选确认后保存。输入框不会回显已保存内容。
3. 打开地图高价值物品显示后，OK-WW 自动核对库街区绑定的游戏角色并连接官方位置同步接口。账号 3 的游戏角色需要进入大世界；服务器返回 `2301` 时，连接会在 30 秒后重新建立，直至游戏角色上线或关闭任务。
4. 库街区来源首次用于小地图时会进行图像匹配检查；显示“等待小地图核对”时停留片刻，让位置同步更新。

直接连接使用 `https://api.kurobbs.com/map/core/gamer/role/getBindRoleInfo` 核对角色，再连接 `wss://api.kurobbs.com/ws-map` 接收坐标。连接维持期间每 10 秒发送一次文本心跳；游戏角色未登录时关闭当前连接并在 30 秒后重连。任务关闭时停止连接。开启 OK-WW 后无需另外打开库街区应用。

token 与固定游戏角色 UID 关联，保存在当前 Windows 用户的凭据管理器中。仓库配置和日志不写入 token。账号切换、任务暂停或退出时关闭连接；账号 3 再次启用任务后自动连接。token 失效时在设置窗口更新。

历史 JSONL 接收目录继续保留兼容：选择目录并核对账号后，可以手动绑定接收会话。保存账号 3 的 token 时优先使用直接连接；其他收集档案不使用账号 3 的直接连接。

## 坐标与时间

库街区消息格式为 `[code,mapId,areaId,x,y]`。接入模块保留原始 X、Y，转换为现有覆盖层使用的坐标时除以 100，距离显示由原有地图单位换算函数处理。`areaId` 保留为来源信息，不直接作为资源包的 `country_id`。`mapId` 必须存在于已下载地图资源中，小地图使用前通过图像匹配检查。

库街区没有提供高度和服务器采样时间，分别保持未知。界面中的“几秒前接收”表示本机接收消息后经过的时间，无法代表端到端延迟。

- 接收后 3 秒内显示同步状态。
- 超过 3 秒显示“更新较慢”，距离显示为约数。
- 超过 8 秒暂停方向导航。
- 超过 12 秒显示数据过期。
- 错误消息和断线立即停止使用该渠道的位置。

相同坐标的不同服务器消息仍是不同观测；反复读取同一条消息不会增加采样次数或刷新时间。`ping` 不延长坐标有效期。图标动画只在两次已接收的位置之间过渡 0.2 秒，不推算未来位置。靠近目标时提示停留等待同步。

“自动选择”优先使用有效 OCR。库街区用于 OCR 无结果时的定位；恢复 OCR 需要连续三个位置合理的截图结果。两种来源不进行坐标平均。库街区位置与近期相同地图的 OCR 记录相差超过 50 米时，暂停使用库街区位置，显示核对提示。

库街区位置变化超过 500 米或地图变化时，需要另一条新的消息确认，重复读取不能完成确认。切换来源或确认传送后会清理方向平滑状态。

人物位置与大地图视图中心分别维护。打开、拖动或缩放大地图仍由图像匹配与原有视图跟踪处理。过期坐标不用于距离确认；路线、目标和收集记录保留，完成标记由用户操作。

## 历史接收文件

读取现有接收程序的 JSONL 日志，不依赖持续覆盖写入的最新坐标 JSON 文件。每次只读取新增的完整行；正在写入的末行等待下次读取。完整行解析错误会报告异常。文件替换或截短会使会话失效。多个同步连接同时使用同一目录时暂停接入，需要关闭同步连接后重新开启单个连接。

历史接收模式只读取新增的完整记录，不读取认证信息。直接连接使用 Windows 凭据管理器中的 token，不读取游戏进程或修改游戏客户端。官方接口是否允许第三方程序持续连接，需要以库街区的现行规则为准；无法保证账号风险为零。
