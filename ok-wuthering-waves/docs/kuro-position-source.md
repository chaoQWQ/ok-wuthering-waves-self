# 库街区位置同步

地图高价值物品显示提供“自动选择”“仅截图 OCR”“仅库街区同步”三个坐标来源选项。

## 设置与使用

1. 启动已验证的库街区接收程序，进入对应游戏角色，并在库街区大地图开启“位置同步”。
2. 在 OK-WW dev 的“实时触发 → 地图高价值物品显示”中选择坐标来源。
3. 打开“库街区位置同步设置”，选择接收目录。目录需要同时包含 `kuro-coordinate-messages.jsonl` 和 `kuro-capture-events.jsonl`。
4. 核对库街区当前角色、游戏账号和本地收集档案，勾选确认，点击“绑定当前会话”。
5. 启用地图任务。库街区来源首次用于小地图时会进行图像匹配检查；显示“等待小地图核对”时停留片刻，让位置同步更新。

本机已经设置的接收目录为 `E:/Codex/2026-10-12/https-github-com-morluto-rea-https/outputs`。接收程序、模拟器及其连接设置由已有工具管理，OK-WW 读取上述本地记录。

收到 `2301` 或断线时，界面显示不可用。重新开启库街区位置同步后，需要核对并绑定新的连接。应用重启、接收目录改变、本地收集账号改变后也需要重新绑定。绑定只保存在当前程序内存中。

消息没有角色 UID。同一连接内更换游戏账号时，需要主动解除绑定并核对新角色；程序无法仅凭 X、Y 自动确认账号身份。

## 坐标与时间

库街区消息格式为 `[code,mapId,areaId,x,y]`。接入模块保留原始 X、Y，转换为现有覆盖层使用的坐标时除以 100，距离显示由原有地图单位换算函数处理。`areaId` 保留为来源信息，不直接作为资源包的 `country_id`。`mapId` 必须存在于已下载地图资源中，小地图使用前通过图像匹配检查。

库街区没有提供高度和服务器采样时间，分别保持未知。界面中的“几秒前接收”表示本机接收消息后经过的时间，无法代表端到端延迟。

- 接收后 3 秒内显示同步状态。
- 超过 3 秒显示“更新较慢”，距离显示为约数。
- 超过 8 秒暂停方向导航。
- 超过 12 秒显示数据过期。
- 错误消息和断线立即停止使用该渠道的位置。

相同坐标的不同服务器消息仍是不同观测；反复读取同一条消息不会增加采样次数或刷新时间。`ping` 不延长坐标有效期。图标动画只在两次已接收的位置之间过渡 0.2 秒，不推算未来位置。靠近目标时提示停留等待同步。

“自动选择”优先使用有效 OCR。库街区用于 OCR 无结果时的定位；恢复 OCR 需要连续三个位置合理的截图结果。两种来源不进行坐标平均。库街区位置与近期相同地图的 OCR 记录相差超过 50 米时，暂停使用库街区位置，显示核对提示。

库街区位置变化超过 500 米或地图变化时，需要另一条新的消息确认，重复读取不能完成确认。切换来源或确认传送后会清理方向平滑状态。

人物位置与大地图视图中心分别维护。打开、拖动或缩放大地图仍由图像匹配与原有视图跟踪处理。过期坐标不用于距离确认；路线、目标和收集记录保留，完成标记由用户操作。

## 接收文件

读取现有接收程序的 JSONL 日志，不依赖持续覆盖写入的最新坐标 JSON 文件。每次只读取新增的完整行；正在写入的末行等待下次读取。完整行解析错误会报告异常。文件替换或截短会使会话失效。多个同步连接同时使用同一目录时暂停接入，需要关闭同步连接后重新开启单个连接。

接入模块不读取登录 token、Cookie 或证书私钥，不修改库街区通信内容、代理设置或游戏客户端。
