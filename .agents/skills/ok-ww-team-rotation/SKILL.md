# OK-WW 自定义队伍轴

本技能用于 `ok-wuthering-waves` 的三人队伍工坊。制作依据来自《一个轴的诞生》的完整画面讲解及当前仓库实现。

## 资料与入口

- 开始制作或分析队伍轴时，阅读 [references/rotation-method.md](references/rotation-method.md)。其中包含视频时间索引、时序分析、读屏验证和实机验收方法。
- 编辑或导出工坊代码时，阅读 [references/repository-api.md](references/repository-api.md)，并重新查看当前源码中的对应函数。
- 涉及新增角色、修改内置角色或登记识别特征时，使用仓库的 `ok-ww-characters` 技能。

## 制作流程

1. 确认三名角色的英文 class name、队伍位置、共鸣链、武器、声骸、共鸣效率、游戏按键、分辨率和帧率。整理用户已经提供的资料；仅询问影响动作可行性的缺失信息。
2. 完整阅读提供的链接内容，包括攻略视频、文字轴、三名角色技能说明及可信的动作帧资料。记录版本和来源；无法获取的资料明确标记待验证，不编造动作帧和资源数值。
3. 制作启动轴和循环轴的动作时间表。每个节点记录执行角色、动作、起始资源、完成证据、最早可衔接时间、切人目标、是否需要变奏和结束资源。
4. 用游戏倒计时与技能冷却变化检查录像中的时序。视频播放时间用于定位画面；出现变速、剪辑、演出冻结时，分别记录经过时间和游戏时间。
5. 阅读三名角色当前代码、`BaseChar.py`、`BaseCombatTask.py`、`CharFactory.py` 和 `CustomCharLoader.py`。按当前工坊加载方式制作三个角色文件，保留既有 class name，明确启动阶段、循环阶段和各角色跨切人保存的状态。
6. 将必要的动作时长与屏幕状态确认结合起来。先确认目标状态出现，再确认其变化或消失；按键请求、动作发生、资源到账分别记录。依赖变奏的节点必须确认协奏已满和目标角色实际入场。
7. 使用真实截图和录像验证识别，使用项目本地 `.venv` 检查语法、导入、角色类型及分享包格式。实机验证必须处于用户授权范围；缺少实机访问时，完成可执行的离线验证并明确记录剩余验证条件。
8. 在真实环境中验证启动轴、连续循环、资源延迟到账、能量不足、输入未生效及战斗结束。依据录屏和日志定位首个未满足的节点，修改后重新运行相关验证，直到用户要求的行为正确运行。
9. 记录经过验证的配置、输入条件和结果，按工坊规则导出分享包并校验。遵循当前仓库的提交要求。

## 实施要求

- 队伍键由三个 class name 排序形成，角色位置在运行时确认。针对既有三人队伍的轴通过队伍工坊保存。
- 每个必要状态等待都有超时；超时处报告角色、阶段、动作、目标状态及当前读数并立即终止当前执行。按住的鼠标与按键必须在清理路径释放。
- 验证使用真实运行材料及成熟库。有限时间内补充资源的动作必须有明确机制依据、完成证据和失败出口。
- 技能时序与资源依赖一起验收。缩短等待时间需要验证动作和资源结果。
- 保留用户当前修改和经过验证的参数；覆盖前保存可恢复副本，导出时写清楚配置要求。
- 保持图像识别与 OS 输入方式，遵循仓库的账号安全限制及实际操作授权。
